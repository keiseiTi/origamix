# Editor harness

Applies to `packages/editor/`. Read the [root guide](../../AGENTS.md) first.

## Ownership

- `src/index.ts` exports the unified Editor; `src/editor.tsx` composes the shared EditorProvider; `useCreateEditor` owns retained view preferences and guarded public commands, `useEditorContext` reads the stable instance, and `useEditorSelector` subscribes to public state; `src/components/` groups the editor layout, canvas, navigation/attribute panels, flow view and editing tools by feature. Feature entry components live in `index.tsx`; local Hooks and pure helpers stay beside their consumers. App owns Agent lifecycle and maps clarification state to the generic target-selection contract.
- `src/components/flow-editor/` is an internal Editor module that owns LogicFlow, React nodes, event tree, node forms and graph translation. Both views share the same engine and edit session. The module reads only its internal session contract; `src/components/flow-editor/flow-editor-loader.tsx` adapts the engine store, supplies schema/materials/catalog/onChange and loads the view dynamically with loading and retry states. Flow node contracts come from Shared; execution belongs to Runtime. HyperInput edits Shared HyperValue envelopes, including context bindings, expressions and functions. Editor never evaluates code; Runtime owns execution.
- `src/session/` retains its lifecycle ownership: `editor-store.ts` creates per-provider Zustand sessions, `editor-context.ts` injects them, `editor-instance.ts` guards retained commands and binding, and `use-bind-editor.ts` connects React lifecycle. `src/hooks/` owns public instance/selector Hooks. Sessions retain bounded complete-Schema undo/redo and injected environment projections (theme, material catalog, target selection and read-only state) in the same session Store. EditorSessionContext is the sole editor-session injection context; retained instance view preferences keep their longer lifetime. Environment updates must not replace Schema or create history. `src/schema/` owns immutable draft commands and schema editing utilities; `src/transactions/` translates snapshots into operation transactions. No module-scoped editor/plugin store. `src/components/canvas/` owns DnD, element wrappers and session-scoped overlays around Runtime DesignRenderer. CodeEditor keeps its Monaco worker setup in its own feature directory; primitive controls belong to UI.
- `src/interfaces/editor-interfaces.ts` and `src/interfaces/property-editor-interfaces.ts` own public editing/extension interfaces. `interfaces/` contains types; runtime plugin helpers belong to `plugins/`. `src/styles.css` registers Editor-owned Tailwind sources. The dynamically loaded FlowEditor loads its LogicFlow styles; the host composes Tailwind and UI foundations.

## Boundaries

- Components, transaction helpers and public types are exported only from `@origamix/editor`; `styles.css` is the sole separate entry. Keep internal imports relative and FlowEditor dynamically loaded. New public exports update `src/index.ts`, not package subpaths or additional build entries. Preserve CSS side effects.

- Never import App, Materials, Server, Desktop, Node.js or Electron. Canvas may import DesignRenderer and rendering contracts from the declared @origamix/runtime root; it must never import runtime execution internals. App provides the concrete catalog and material groups; FlowEditor reads the injected catalog rather than Antd imports.
- Editor does not interpret AI Runs or clarification expiry. `targetSelection` receives host-owned candidates, highlight, disabled state and a selection callback. Read-only defaults are generic; App supplies business-specific messages.
- No HTTP, Working recovery, Revision, Apply, App Store or host credential ownership here. The unified Editor receives a loaded schema, stable sessionKey, registration, explicit theme and change/flush callbacks.
- The schema prop is the initial projection for one sessionKey, not a second authoritative store. Ordinary saves do not replace it or reset history; an explicit new sessionKey switches the engine through an unmounted boundary before creating the replacement session, without a React key. Registration or EditorInstance replacement uses the same boundary; old plugins, bindings and portals clean up before the replacement mounts. App retains in-flight drafts and advances the committed Working version only after Server success.
- Attribute edits preserve unrelated stored props. The attribute panel lists obsolete fields and removes them only through the explicit cleanup action; snapshot diff emits unset operations. Loading and immutable Revisions are never rewritten.
- Each flush translates against the last acknowledged Working snapshot through `createEditorTransaction`. Typed operations are preferred; the internal candidate fallback is only for operation protocol gaps. Prop edits and Flow edits use the same host queue.
- `components/flow-editor/flow-graph.ts` keeps LogicFlow presentation dimensions in `extensions.flowGraph`, stripping `width`/`height` from executable node props so Runtime can validate them against Shared without allowing layout fields in the execution contract.
- Preserve scoped async results, failed drafts and flush rejection before page/mode/preview transitions. Readonly view changes must not reach the host; never add a separate save path to a panel or flow node.
- CodeEditor receives theme explicitly or from the Editor context. CodeEditor configures Monaco workers before creating models; its package-owned `?worker` imports are transformed by the consuming bundler (currently Vite). App must not maintain a second worker bootstrap. This package must not import App preferences.
- Materials owns its concrete panel configuration types behind its editor entry. `JsonAttributeConfig` is the editor-owned structured-field shape; no imports back into Materials are allowed. Custom attribute renderers receive the current field value, read-only selected-element props/field names and an onChange callback; key draft controls by element/field/value so local edits cannot cross selection or external updates. Live custom controls may set `resetOnValueChange: false` to keep input focus; they must reconcile external value changes themselves. Existing JSON attribute fields remain available.
- Property controls remain limited to selected-element props; plugins use the public node-operation contract and explicitly injected save callback. Do not expose raw engine, HTTP, filesystem, App Store or a generic host SDK.

## Verification

Run `pnpm --filter @origamix/editor lint`, `typecheck`, `test`, `build` and all four root gates. Existing snapshot-operation and graph safety tests live in `test/session/`, `test/transactions/` and `test/flow-editor/`; App owns persistence-session failures and stale-response checks. Do not add presentation tests.

UI verification must exercise actual visual/flow switching, event selection, history, code-editor workers, preview and both themes. Successful HTTP is not rendering evidence.

- Flow forms follow the reference value kinds without a JSON kind or separate comparison operators. Requests edit headers/query/body through functions; conditions use expressions/functions. Coalesce LogicFlow model events until the mutation completes, then send the full executable flow and layout through the shared engine change callback with `immediate: true` in logic mode. Do not add panel-owned persistence.

- Flow read candidates come only from Manifest.context.variables; write candidates only from context.writable; method choices only from context.actions. Never merge propsSchema into these lists. Keep event.payload separate from durable element state. Root materials are injected separately and must not enter the draggable palette.

- `src/prototype/canvas-prototype.tsx` is the public surface of the isolation feasibility experiment. The adjacent CanvasPrototypeSession owns the sandboxed iframe and MessageChannel host; mountCanvasPrototypeFrame owns frame initialization and command handling, with registration injected by the caller. The experimental protocol stays internal here until a production migration moves the full contract to Shared. It exposes only restricted commands and snapshots, never Engine. It reuses CanvasEditor, independent session history and Schema editing tools, without HTTP, persistence or production replacement behavior. Keep the experiment permission-isolated from the production Editor; verify native hit testing and movement through actual interaction.

- Layout ownership and rollout are documented in [material layout](../materials/src/layout-properties.ts). Material.acceptsChildren comes from Manifest; default occupancy comes from Material.layout. Never reintroduce isContainer/isBlock or design-only layout wrappers. Selection refs/events attach to the shared Runtime layout node; candidate decorations use portals. Parent layout determines insertion axis.

- Overlay materials declare editorConfig.presentation as overlay. Session openOverlayIds is transient: selecting an overlay or descendant reveals its ancestor path; closing never changes Schema, history or business events. Overlay insertion/movement targets the Schema root; Ant Design getContainer mounts into its Runtime layout frame, which is positioned relative. Content frames retain selection/drop geometry, and masks stay within the page.

- The host passes one stable instance to Editor and owns tool dialog composition. Export SchemaEditor/GlobalVariablesEditor as context-bound editing content with onDone; never add host tool identifiers or Revision/Apply dialogs to Editor. Session binding is internal and detached on unmount; public mutation commands reject read-only/detached sessions, and asynchronous mode changes must reject stale bindings after the host flush.

- `src/plugins/plugin-host.ts` owns session-scoped plugin lifecycle. `useCreateEditor({ plugins })` captures definitions once per retained instance; changing plugins requires a new instance. defineEditorPlugin<Props>().withProps(props) binds dynamic render parameters; define these plugins outside render or retain their definition. useCreateEditor publishes parameter updates after commit to per-instance, per-plugin stores; only plugin render boundaries subscribe, without restarting setup or changing the engine/material registration. IDs must be nonempty and unique. Setup runs right-to-left, cleanup in reverse; permission/environment updates do not restart plugins. Setup receives a session-scoped command facade and AbortSignal: register partial-setup resources with the signal immediately, since a throwing setup cannot return cleanup. The signal aborts on failure/unmount; returned cleanup functions must release remaining resources. Old facades reject commands after detachment. Toolbar/top/bottom rendering is integrated in `src/components/editor-layout/editor-toolbar.tsx`: local areas compose before all; reusable area components never invoke all. `editor.save()` guards duplicate/stale saves and optional flush; the host retains Revision/HTTP ownership. Toolbar prop is removed; App composes workspace.toolbar, while Editor exports mode/viewport/history toolbar plugin factories and their reusable tool components. History state and shortcuts remain in the existing session; material.extend/getPanels compose right-to-left through plugins/material-plugins.ts; property fields/defaults must match the installed Manifest. Material-specific Form matching belongs to Materials plugins, never AttributePanel. material.render, region replacement and flow extension remain unintegrated.

- `interfaces/editor-operation-interfaces.ts` owns public node operations and event payloads; `session/editor-operations.ts` adapts queries/commands to the existing validated session path. `session/editor-events.ts` emits accepted transaction snapshots, isolates observer errors and rejects synchronous reentrant mutation. Drag/delete/panel/history changes share this event path; no plugin persistence path. Schema queries/events use frozen copies, plugin subscriptions and command facades expire with binding. Preserve final-index move semantics and avoid reporting shifted siblings as moved.

- Public plugin usage and scope are documented in [PLUGINS.md](PLUGINS.md). Setup may query/register, but document edits, save and mode changes must reject until all plugins finish initialization; App deliberately filters bootstrap edits. Do not move history storage/shortcuts into toolbar plugins without preserving the single session history and Working path.

- Material registration.plugins is appended to the retained host plugin list, snapshotted once per Editor session and run by the same host. Keep core plugin state fixed across environment updates; a new registration requires a new sessionKey. Panel IDs are optional but unique when present. Runtime field wrappers remain in Materials; do not apply a second design Form.Item wrapper.

- The source root explicitly references its ambient worker/CSS declarations so editor-facing consumers can typecheck without inheriting Vite client types. These references are type-only; never emit runtime imports of declaration files or require consumer-side copies of the worker declarations.

- Attribute-panel rules and field/event rendering stay local to `components/attribute-panel/`; `use-attribute-panel.ts` coordinates selection and panel state. `components/flow-editor/hooks/use-flow-canvas.ts` owns the LogicFlow lifecycle and shared-session commit bridge. Store consumers require explicit selectors; use `useShallow` for multi-field selections.
