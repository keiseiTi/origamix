# 布局配置

每个项目只有一份固定名称的「布局配置」，用于放置公共标题、品牌区和页面导航。开启后，它包裹项目中的所有页面。页面继续负责自己的业务内容，布局通过「页面内容区」显示当前页面。

## 开启与编辑

1. 在左侧项目的「…」菜单中选择「启用布局配置」（新建项目时也可以打开「启用布局配置」开关）。开关保存到 `origamix.project.json` 的 `layout.enabled`，立即作用于项目。
2. 启用后，左侧项目导航显示「布局配置」，点击打开编辑器。
3. 在编辑工具栏点击「从预设开始」，选择空白、顶部导航、侧边导航、顶部与侧边、侧边与内容顶部，或直接编辑。
4. 点击工具栏「布局属性」，配置 Layout 的布局结构、顶部、侧栏、页脚、导航、宽度和内容内边距。也可将容器、文字、按钮放入区域中。预设只调整根配置，保留已有区域内容；确认后可以整体撤销。

布局与页面复用同一套编辑器、草稿、版本和历史操作。它们各自保存内容，切换标签不会把布局草稿写进页面。

## 页面内容区与导航

布局必须保留且只能有一个可达的「页面内容区」（`PageOutlet`），它不能拥有子节点。在编辑器中它显示占位，在预览和独立项目中显示真实页面。删除唯一内容区或生成非法结构时，修改会被拒绝，之前的草稿保留。

布局根节点为 `Layout`，内部 `LayoutRegion` 分别承载顶部、侧栏、内容、页脚及主体。它们由根属性统一管理，不提供单独新增入口，也不允许直接删除或移动。关闭区域只隐藏，已有内容保留，重新开启恢复。

Header、Sider 内置 Ant Design Menu，分别提供横向和纵向导航；可通过「顶部导航」「侧栏导航」分别关闭。它们自动读取项目页面目录，应用外壳把稳定的 pageId 解析为路由并同步当前选中项，无需手写链接。侧栏支持折叠、折叠宽度、默认状态及响应式断点。

切换结构和区域开关会在同一次草稿修改中更新内部节点，撤销一次整体恢复，不会额外保存版本。

布局首期用于公共结构，业务流程、事件绑定和全局变量仍在页面中配置。当前不提供多个布局、布局重命名或单页覆盖。

## 通过对话修改

在「布局配置」中返回对话，描述要修改的布局，例如：

> 创建顶部品牌栏和左侧导航，把页面内容区放在右侧，保留足够的内容宽度。

当前对话目标是项目布局，Agent 读取布局草稿和可用物料。它通过校验后更新布局 Working，不会修改页面内容或项目开关。布局对话与页面对话分别保留历史。

运行时可以停止生成；断线后先使用重试入口确认运行状态。恢复不会自动重做模型请求。布局 Agent 运行期间，项目布局开关暂时不可关闭。

## 预览完整应用

布局和页面的预览按钮都打开[完整应用预览](/guide/preview)，使用当前布局与各页面的 Working 草稿。通过导航或顶部页面选择切换页面，通过刷新按钮重新读取快照。

进入预览会先提交当前项目已打开编辑器的草稿；提交失败时保留编辑视图。预览不要求先保存版本或应用。

## 保存与应用

检查完成后，先点击「保存版本」，再点击「应用到项目」。布局 Apply 只更新固定的 `src/origamix-layout/schema.json`；页面仍需分别保存和应用。

开启布局但尚未应用布局文件时，工作台仍可预览草稿；独立生成应用会提示先保存并应用布局。运行与部署方式见[运行生成项目](/start/generated-project)。

恢复历史只把内容恢复为草稿，不创建新版本、不应用，也不改变项目开关。需要保留检查点时再次显式保存。

## 关闭与故障处理

在项目的「…」菜单中选择「关闭布局配置」后，左侧隐藏「布局配置」入口，应用直接显示页面；已有布局草稿、历史和对话保留，重新开启后可继续编辑。开关只由项目控制。

遇到版本冲突时，先确认最新状态，再决定如何处理本地草稿。遇到应用结果待确认时，使用原请求恢复结果，避免重复发起新的应用。目标文件被外部修改时，先检查并处理外部变化；布局暂不提供从外部文件覆盖 Working 的入口。

此功能面向新建项目，不包含旧项目应用外壳迁移。接口与数据结构见[Layout 契约与接口](/architecture/layout)。
